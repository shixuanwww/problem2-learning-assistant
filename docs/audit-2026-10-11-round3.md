## 2. 本轮修掉的（按性价比从高到低）

### 2.1 🔴 关键词充足性会把"资料没讲"判成"资料充足"（P1，改动 ~15 行）

**修前实测**（离线/无 Key，评审机最可能跑的路径；资料只有「小数的认识 / 小数加减」）：

```
小数乘除法怎么计算 => sufficient=true | 回答是「整数乘除法」那段
分数的乘除法怎么算 => sufficient=true | 回答是「整数乘除法」那段
```

原因：覆盖率是"top-5 命中片段的词项**取并集**"算的 ⇒ "小数"命中一份资料、"乘除"命中另一份资料，
拼起来就过了 0.5。与题面 §2.4 1.2「资料不足以支持答案时应提示资料不足」直接冲突。
（注意：配了 Key 时模型会自己判"资料不足"并降级 —— 所以这是**无 Key 主路径**的缺陷，
而演示里选的是"二次根式"这种完全无关的问题，恰好躲过了它。）

**修法（三步，都可复现、可回退）**：

1. 词项只用**中文二元组**（去掉 3 元组）。3 元组在语料里几乎不连续（问"分数加减"，语料写"分数**相**加减"），
   只会撑大分母 —— 实测把"分数加减怎么通分"这种正常提问拖到覆盖率 0.44 而误判"资料不足"；
2. **抽取式回答**（没配 chat Key，没有模型再把关）时加一道**话题锚点**：
   top1 片段必须命中"提问里第一个实词段的头两个汉字"（`KEYWORD_REQUIRE_TOPIC_ANCHOR`）。
   有 Key 时不启用 —— 模型是最后一道闸门且**只能降不能升**，没必要提前用启发式把问题拒掉；
3. **章节标题参与匹配**：m03 的正文一次都没写"认识"二字，标题却叫「1 小数的认识」，
   不把标题算进去，问"小数的认识是什么"反而被判资料不足（实测复现）。

**修后实测**（同一批资料，11 个问题）：

| 资料里讲过 | 结果 | 资料里没有 | 结果 |
|---|---|---|---|
| 整数加减法是什么 / 整数乘除法怎么算 / 小数加减法怎么做 / 小数的认识是什么 / 分数加减怎么通分 / 同分母分数怎么相加减 / 进位规则是什么 | **全部 `sufficient=true` 且出处正确** | 小数乘除法怎么计算 / 分数的乘除法怎么算 / 二次根式怎么化简 / 几何图形的周长怎么算 | **全部 `answer=null`** |

用例 34（不能靠多片段拼成"充足" + 讲过的仍要能答）、用例 35（标题参与匹配）钉住。

### 2.2 🔴 同义知识点合并只靠 3 条别名（P1，改动 ~25 行 + 数据）

**修前实测**：真模型抽 3 份很短的资料就得到 **25–29 个知识点**，其中
`整数加减法 / 整数加法 / 整数减法`、`小数加减法 / 小数加减`、`分数的意义 / 分数`、
`整数乘除法 / 整数乘除` 这些**同义写法各占一个节点**（`canonicalize` 实测不合并）⇒
考频被拆散到多个节点、计划里重复出现。

题面 §2.4 1.1 明确要求"尽量把名字不同但本质相同的知识点合并"。

**修法（保持"不自动合并"的安全边界）**：

1. `data/aliases.json` 从 3 条扩到 16 条，覆盖样例/模型输出里**明显同粒度**的写法
   （`整数加法`/`整数减法`/`整数乘除法`/`整数乘法`/`整数除法`/`小数加减法`/`小数加法`/`小数减法`/
   `分数的意义`/`小数加减法从末位算起`/`乘除竖式计算的进位与退位` …）；
   **不并** `同分母分数相加减` / `异分母分数相加减` 这类真正的不同技能点；
2. **合并候选提示**：`mergeCandidates()` 按名字的字符**二元组 Jaccard ≥ 0.6** 列出疑似同义点，
   网页壳 `/api/graph` 返回，人工确认后再写别名表。
   为什么不用"名字包含关系"：`分数` / `分数加减` 是**整体-部分**关系而不是同义
   （Jaccard 0.33 会排除）；`小数加减法` / `小数加减` 才是同义（0.75 会列出）。用例 38 钉住这两面。

### 2.3 🔴 考频与真实题目集脱节（P2 真 bug，改动 ~15 行）

**修前实测**：

```
首次入库 T1 考点[整数加减]      => pointMention=[1,0]
同题重入库、考点改成[整数乘除]  => pointMention=[1,0]（应为 [0,1]）
pointRank(2)                   => [整数加减, 整数乘除]  ← 考频榜是错的
```

修前只在"首次入库"时 +1，重入库直接替换 `problems[idx]` 但不动考频。
**可达路径**：网页壳重传同名真题；或重启时用模型重新抽题（模型输出不稳定，我两次 full-demo 抽出的点集就不一样）。

**修法**：考频改成"由当前题目集决定" —— 重入库先扣旧考点计数、再加新考点计数
（同一考点集合反复入库净变化为 0，幂等性不丢）。用例 36 钉住。

### 2.4 🔴 合并 + 重启后再用旧名上传资料 → 静默丢数据（P2 真 bug，改动 ~20 行）

**修前实测**：

```
mergePoints(整数加减法 → 整数加减)     => alive=[整数加减]
重启（新实例读回 graph.json）后，
再用旧名「整数加减法」上传资料 b.md    => alive 仍只有 [整数加减]；queryPoint(整数加减) 的资料里没有 b.md
```

原因：`mergePoints` 只把旧名从索引删掉、没记"并到哪去了"；而 `loadGraph` 重建索引时**不跳过 dead 点**，
重启后旧名又指向那个 dead 点 ⇒ `ensurePoint` 命中它，资料被挂到一个查不到的节点上（体系里看不到、计划里也没有）。

**修法**：`PointNode` 增加 `mergedInto`（落盘 + 载入校验），索引保留旧名，`findPid/ensurePoint/queryPoint`
统一走 `redirect()` 落到合并目标；`record(Do)` 用新的 `stateKeyOf()` 把掌握度记到合并目标上
（否则旧名做题会在 `state` 里留下图里查不到的孤儿 key）。用例 37 钉住"合并 → 重启 → 再接入 + 用旧名做题"。

### 2.5 🔴 "让 AI 决定下一步学什么"其实没有模型参与（P2，改动 ~80 行）

**修前**：`chat()` 只在"抽取"和"问答"里被调用；`proposePlan` 的调用方只有测试、`/api/propose`
和 demo 里**手写**的非法草稿 ⇒ 题面 L3 1.2「让 AI 结合上下文决定下一步学什么、怎么学」实际 100% 由规则完成，
评审一问"AI 在哪决策"就会穿。

**修法**：新增 `proposePlanFromModel(net)` —— 把"知识点清单（拓扑序 + 前置 + 资料 + 真题 + 掌握度）"
交给模型，要它返回 `{"plan":[{pointName, actions}]}`，再走**同一套** `proposePlan` 校验
（覆盖完整 / 恰好一次 / 拓扑序 / 资料与真题必须真实存在），通过则采用、不通过则不执行并回落规则版计划，
接受与拒绝都写 `decisions.json`。

顺带修掉一个**接口用错**的坑：`response_format: {type:"json_object"}` 要求顶层是**对象**，
修前提示词写"只返回数组"，模型只能包一层 `{"plan":[…]}`，于是每次都被拒在"草稿必须是数组"上
—— 看着像模型乱来，其实是调用方式错了。现在提示词写对象 + 系统侧 `unwrapDraft()` 剥壳。

**修后实测**（`demo/full-demo.ts`，本机有 Key）：

```
## 补充演示：让真模型提一版计划 → 校验 → 通过则采用 / 拒绝则回落（§4.13）
  ⇒ by=model｜accepted=true
  ⇒ 采用模型提议的计划（覆盖 22 个知识点）
  ## 补充演示：模型提议被拒 → 回落规则版计划（§4.13）
  ⇒ accepted=false
     拒绝理由：真题「2024 期末 第9题（不存在的真题）」不存在（禁止模型编造真题）
     拒绝理由：知识点「积分中值定理」在图中不存在（或已失效）
```

用例 39 钉住三条出口（合法采纳 / 非法拒绝且留痕 / 非 JSON 标 `by="none"` 不抛异常）。
网页壳 `/api/propose` 支持 `{"useModel":true}`，`/learn` 页面加了两个按钮（真模型提议 / 喂非法草稿）。

## 4. 这轮**故意没改**的（含理由）

| # | 问题 | 为什么没改 |
|---|---|---|
| 1 | 上传是**同步**处理（`/api/upload` 里 `await` 抽取后才返回），题面工作流写的是"上传资料 → **后台**解析资料" | 真后台化要引入任务队列 + jobId + 状态轮询 + 前端轮询，属于**结构性改动**；当前演示规模（几份短 md）同步处理 <1s，收益不抵复杂度。已在 README §9 如实声明为已知限制 |
| 2 | `record(Read)` / `record(Skip)` 只留痕，不影响 `state` 与计划 | 题面只要求"学习记录"能记下来；给 Read/Skip 编一套掌握度增量属于**拍脑袋的数值**，宁可先留白也不写假逻辑。真要做得先定语义（Skip 是"暂缓"还是"不会"？） |
| 3 | `record(Do)` 多知识点题时，history 的 `before/after` 只记**最后一个点**的掌握度 | 纯观感问题（不影响计划/判分），要改得动 `HistoryEntry` 结构；性价比低于 §2 那几条，留作已知小坑 |
| 4 | 向量检索失败后不缓存失败原因，每次问答都会重新 embed 全部片段 | 只在"配了 embedding Key 但服务抖动"时才有额外成本；当前默认路径（关键词）不触发 |
| 5 | `.env` 与 `data/` 都是**相对 CWD**，必须从仓库根启动 | 题面交付的是"能在本机跑起来"的项目，README 的启动命令都从根目录给；再加一遍路径解析收益很小 |
| 6 | 语义合并（embedding 找同义点）仍未做 | 见 §2.2：已给"二元组 Jaccard 候选提示 + 别名表"这条路；embedding 版本要接向量服务、还会把"自动合并不可逆"的风险重新引入，性价比低（README §9 已声明） |

> `mergePoints` 本身由用例 37 覆盖（合并 → 重启 → 再接入 → 用旧名做题）。
