# 02 · 知识网络（`network.ts`，`SimNet` 类）

## ① 这段代码干什么

题面 trait 里除了 `analyzeRes` / `analyzePro` / `ask` 之外的方法都在这里：
`integrate`（把分析结果并进体系）/ `makePlan`（生成学习计划）/ `pointRank`（考频榜）/
`queryPoint`（查一个点的资料+真题+题型）/ `record`（记一次学习行为并更新掌握度）/
`mergePoints`（合并两个知识点），外加拓扑排序、环检测、`graph.json` 的序列化与载入。

## ② 关键设计决策 + 为什么

| 决策 | 为什么这么定 |
|---|---|
| **❌ 不 import `plan.ts`（避免环形依赖）** | `makePlan` 要给每个知识点填"学习动作"，而动作规则在 `plan.ts` 里。若 `network` 直接 import `plan`，而 `plan` 又要用 `network` 的类型 ⇒ 环。**解法**：`network` 只声明一个 `ActionFiller` 回调接口，由外部 `wireActions(net)` 注入实现。 |
| **`integrate` 是幂等的** | 同一份资料传两次，**不会**产生重复点、不会重复加资源、不会把考频刷高。判据：点名归一化后同 key 就**复用已有 pid**。 |
| **考频 `pointMention` 只在"该题首次入库"时 +1** | 否则重复上传一次真题，考频就翻倍，"考频榜"就没有意义了。 |
| **隐式建点只对 `edges` 端点生效** | 资料抽取时，边提到了但 `points` 列表里漏了某个点 ⇒ 补上（这是抽取的**容错**）。但**模型提议里提到不存在的点一律拒绝**，绝不隐式建点（否则模型可以凭幻觉往图里塞点）。 |
| **拓扑排序 = Kahn 分层** | 同一次"入度为 0"的点属于同一层 ⇒ 同层内的点是**互相独立**的，可以任意换序。这就是"调整计划"的可行域从哪来的。 |
| **🔴 层内排序键 = `(已掌握 ? 0 : 1, 掌握度, -考频, 名字码点序)`** | 依次表达四个意图：① **没掌握的排前面**（已掌握的点排最后，对应题面 L3 完成标志③"降低已掌握内容优先级"）；② 掌握度越低越靠前；③ 考频高的先学（性价比）；④ **最后一项是为了"确定性"** —— 前三个都相同时按名字排，保证同一份数据每次跑出**完全一样的计划**（不然演示会"随机变"）。⚠️ 第一项**修过一次反向**：此前写成 `已掌握 ? 1 : 0`，升序一算已掌握的点会被排到**最前**（用例 30 钉住）。 |
| **环的处理 = 打破环 + 告警，不抛异常** | 题面要求计划必须能生成。有环时强行抛错会让整个演示挂掉。做法：拓扑排不进去的点，**按同一个排序键补齐到末尾**，保证"每个点恰好进计划一次"。同时记 warning 说明有几个点是被打破环补进来的。 |
| **`cycles()` 独立计算，不依赖调用顺序** | 早期版本是"复用上一次拓扑排序剩下的点"，导致**必须先调 `makePlan` 再调 `cycles`，否则恒返回空** —— 这种隐性耦合后来被我改成独立 DFS（白/灰/黑染色找回边）。 |
| **`mergePoints` 保 pid 不变** | 被合并的点标 `dead`、从"名字→pid"索引里移除；其余点的 `prev`、真题的 `points`、`history` / `answers` 里指向旧点的引用**全部改写**成新点；掌握度按"答题次数加权平均"合并。 |
| **`record` 只更新它涉及的点 + 该题型** | 一次 `Do` 会改：① 该题涉及每个知识点的掌握度；② 该题题型（`kind`）的掌握度。对应题面"更新**知识点、题型掌握度（两者）**"。 |
| **`record` 遇到"图中不存在的点"只告警不静默** | 否则会留下"图里查不到、但 state 里存在"的**孤儿 key**，很难排查。现在会打一条 warning 说明该点不在体系里。 |

## ③ 可能被追问的问题

**Q：同层内换序，凭什么说是安全的？**
> 因为"同层"的定义就是**入度为 0 的点集合** —— 它们的前置全部已经被排在更前面的层里了。
> 同层之间没有 `from → to` 约束，所以换序不违反任何前置关系。这是本题"调整计划"的可行域边界。

**Q：那如果我想把某个薄弱点提前，但它前置没掌握怎么办？**
> **排在它的前置点之前是违反题面硬要求的，不能做。** 我只做三件事：① 同层内把它排到最前；
> ② 在本点动作序列最前补一个"前置点的资料/讲解"；③ 给它加量（主题 + 回炉题）。
> 对应题面"调整计划"必须在拓扑序允许范围内。

**Q：为什么 `makePlan` 不返回 `LearnPlan` 的深拷贝、而是直接算一遍？**
> 它本来就是**纯计算结果**：每次调用都按当前 `state` / `pointMention` 重算。
> 这样"做错一道题 → 重新 `makePlan` → 计划变了"是天然成立的，不需要维护计划副本和失效逻辑。

**Q：`mergePoints` 的"加权平均"具体怎么算？**
> 按两个点各自的**作答次数**加权：`(掌握度A × 次数A + 掌握度B × 次数B) / (次数A + 次数B)`。
> 两边都没作答过（次数都是 0）就取两者的较大值。合并后旧 key 从 state 里删除。

**Q：`pointRank(n)` 和 `makePlan` 的排序一样吗？**
> 不一样，别混。
> `pointRank` 是**考频榜**：只按 `pointMention` 降序（同频按名字），是"哪些知识点考得多"。
> `makePlan` 是**学习顺序**：还额外考虑拓扑约束、掌握度、已掌握与否。

**Q：`queryPoint` 里为什么真题也要归一化后再比？**
> 因为资料里写的点名和真题里写的点名**可能一个是规范名、一个是别名**。
> 两边都先过"别名表 + 归一化"再比，才能匹配上。这是全项目**唯一的比较口径**（`keyOf()`）。

⚠️ **Q：同一道真题重新入库（考点变了），考频会跟着变吗？**
> 会。现在的口径是"**考频由当前题目集决定**"：重入库时先扣掉这道题**旧**考点的计数，
> 再按**新**考点 +1 ⇒ 既幂等（同一考点集合反复入库净变化为 0，不会刷高），
> 也不会与实际问题集脱节。这是第三轮修的真 bug：修前只在"首次入库"时 +1，
> 把同一道题从「整数加减」改成「整数乘除」后 `pointMention` 还是 `[1,0]`，
> `pointRank` 会把**没有任何真题覆盖的点**排到第一（网页壳重传同名真题、或重启时用模型重新抽题都会触发，
> 因为模型抽取结果不稳定）。用例 36 覆盖。

**Q：题面要求"尽量把名字不同但本质相同的知识点合并"，你怎么做的？**
> 三层，都不"自作主张"地自动合并：
> ① 入图前：`normalize()`（全角/空白/大小写/连接符）+ `data/aliases.json` **别名表**（人工声明的同义写法）；
> ② 入图后：`mergePoints()` 真正把两个点并成一个（含前置边、资料、考频、掌握度的合并），
>    并且**保留 pid 不位移**（其余点的 pid 不会错位）；
> ③ **候选提示**：`mergeCandidates()` 按名字的字符二元组 **Jaccard ≥ 0.6** 列出疑似同义的点
>    （"小数加减法 / 小数加减"相似度 0.75 会列出；"分数 / 分数加减"是整体-部分关系，0.33 会被排除），
>    网页壳在 `/api/graph` 里返回，人工确认后写进别名表。
> **为什么不自动合并**：自动合并会静默吃掉一个知识点、不可逆；宁可给人一份候选清单。

**Q：环是怎么产生的？**
> 路 A（模型抽取）是**逐块**做的：资料被切片后每块独立抽边。块内自洽，**跨块就可能不自洽**
> （比如块 1 说"A 是 B 的前置"、块 2 说"B 是 A 的前置"）。
> 路 B（md 里显式声明）不会有这个问题，因为边是人写的一条条列出来的。

⚠️ **Q：`SimNet` 实现了题面那个 7 方法 trait 吗？**
> 是的，7 个都在。（`ask` 不在 `SimNet` 上 —— 详见 `04-问答与检索.md` 的对应问题。）
