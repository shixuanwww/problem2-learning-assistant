# 05 · 抽取流水线与降级（`analyze/parse.ts` / `schema.ts` / `llm.ts` / `analyze.ts`）

## ① 这段代码干什么

把**一份 md 文件**变成 `AnalyzeResReq` / `AnalyzeProReq`（带 `points` / `edges` 的结构化结果）。
四个文件各管一段：

| 文件 | 职责 |
|---|---|
| `parse.ts` | 纯文本解析：按标题切章节、超长再切段落；读 md 里的**关系声明**（路 B）；收集文件、读文件 |
| `schema.ts` | **手写** JSON 校验器（不引 ajv）：校验模型返回的 `{points, edges}` 形状对不对 |
| `llm.ts` | 模型调用（chat / embedding）+ **自带 15 行 `.env` 加载** + 无 Key 时抛错（由上层降级） |
| `analyze.ts` | 编排：**三级路径**逐级回退，产出最终结果 |

## ② 关键设计决策 + 为什么

| 决策 | 为什么这么定 |
|---|---|
| **🔴 三级路径，逐级回退**：`路B（md 声明）→ 路A（模型抽取）→ presets 兜底` | 单靠模型不行（评审机可能没 Key / 没网），单靠声明也不行（真实资料不会写这种声明）。<br>所以：**有声明就直接切（离线可用）**；没声明才调模型；模型也不行才用 `data/presets/` 里的预置结果。**保证"资料 → 知识体系"这条链在任何环境下都不断。** |
| **手写校验器，不引 ajv** | 要校验的形状只有两种（`{points:[{name}], edges:[[{name},{name}]]}` 和 `{points:[{name}]}`），引一个校验库的代价（依赖 + 体积）远大于收益。**零依赖是硬约束。** |
| **校验失败重试 1 次，再失败就报错跳过该文件** | **绝不写脏数据**：一个点数不是字符串的结果进了体系，后面全乱。宁可这份资料暂时进不去，并明确报错。 |
| **`点名的空/非空` 也校验（`trim()` 后非空）** | 模型很爱返回 `{"name": ""}`，不挡的话会往图里塞一个空名字的点。 |
| **`llm.ts` 自己读 `.env`，而不是用 `node --env-file`** | 🔴 `--env-file=.env` 在**文件不存在时会让 Node 直接退出**（`Error: .env: not found`），那就根本谈不上"无 Key 优雅降级"。自己读的好处：① 没有 `.env` 就跳过；② 能**剥掉 BOM**（带 BOM 会让 `--env-file` 静默失效）；③ **已存在的真实环境变量优先**，不覆盖。 |
| **Key / Base URL 全部走环境变量，绝不硬编码** | 演示、提交、评审机三种环境 Key 都不同；硬编码一定会泄露。 |
| **`embed` 与 `chat` 的 Key 分开判定** | 两个服务（向量 / 对话）是两套 Key，可以只有其一。分别降级：无向量 Key → 关键词检索；无对话 Key → 抽取式回答。 |
| **超长文本按标题切、再按段落切，逐块分析后**取并集** | 单次请求塞不下整份资料；而且"块内抽取"的准确率比"整篇抽取"高（上下文更聚焦）。代价就是**跨块的边可能不自洽 → 产生环**（见 `02-知识网络.md`）。 |
| **`## 知识点:` / `## 前置:` 这种声明格式是我自己定的** | 题面没有规定资料格式。定一个**人也能读、机器也能解**的极简约定，就能让离线路径真正跑起来。属于题面允许的"自行设计"。 |
| **兜底 `presets` 只在"前两级都拿不到"时使用** | `data/presets/analyze-req.json` 是预置结果，**不是正常路径**。如果用它在正常路径上"假装成功"，那"资料→知识体系"就是假的（题面演示第 1 条要的正是这一步）。所以我把调用点放在**两次失败之后**。 |
| **兜底触发时打 `console.warn`** | 让人知道"这份资料是靠兜底进来的"，而不是静默。 |

## ③ 可能被追问的问题

**Q：演示第 1 步"接入资料"，到底是真的解析还是读预置结果？**
> `l1-demo` 是**真的读** `data/materials/*.md`，用 `parse.ts` 解析出 `points` / `edges`（路 B）。
> `full-demo` 是**真的调模型**逐块抽取（路 A）。**两边都不是读预置结果**。
> `data/presets/` 只在"md 里没写声明、模型又不可用"时才兜底，而且触发时会打 warning。

**Q：模型返回的 JSON 里带了 markdown 代码围栏（```json … ```）怎么办？**
> `safeParseJSON` 会先**剥掉围栏**再 `JSON.parse`。同时请求里也带了 `response_format: {"type":"json_object"}` 要求它返回纯 JSON，双保险。

**Q：为什么不直接 `JSON.parse` 模型输出？**
> 因为 `JSON.parse` 只保证"是合法 JSON"，**不保证"形状对"**。
> 比如 `{"points": "整数加减"}` 是合法 JSON，但 `points` 不是数组 —— 这就是 schema 校验要挡的。

**Q：`analyzePro`（真题）的 `points` 从哪来？**
> 两条路：① 真题 md 里有 `## 涉及知识点: …` 声明 → 直接用；② 没有 → 调模型判"解这道题需要哪些知识点"。
> 无论哪条，**`problem` 都原样带回**（`name` / `content` / `kind` 一个不改），只补 `points`。

**Q：为什么真题要有 `kind`（题型）？**
> 因为题面第 4 步明确要求更新**"知识点、题型掌握度"两者**。
> `kind` 从真题 md 的 `## 题型: 计算` 读；缺失记 `"未分类"`，然后 `kindState` 用**和知识点完全相同的公式**更新。

**Q：`.env` 加载为什么放在 `llm.ts` 的模块顶层？**
> 因为它必须在任何读取 `process.env` 的常量之前执行。放在顶层，**import 这个模块时就会执行一次**。
> 代价是"import 有副作用"，但在这类小工具里是划算的（比引 dotenv + 显式初始化更简单）。

**Q：如果一份资料模型抽不出任何点，那份资料就丢了吗？**
> 不是直接丢：先试 `presets` 兜底；兜底也没有才抛错让上层跳过，并且**明确打错误信息**。
> 关键是**不会往体系里塞半个点或者脏点**。

⚠️ **Q：路 A 抽出来的知识点粒度，和真题 md 里的声明对得上吗？**
> **不一定对得上，这是已知问题。** 模型可能把"整数加减"拆成"数位对齐 / 加法逢十进一 / 进位规则 / 退位规则…"，
> 而真题 md 的 `## 涉及知识点: 整数加减` 写的是粗粒度的名字。
> 后果：可能出现"**真题提到了、资料没覆盖**"的点（这种点在计划里只有 Explain + 做题，**读不到资料**）。
> 我在 README §9 把这条列为已知限制。**被问到就直说，不要掩饰。**
