# 01 · 数据契约与持久化（`types.ts` / `normalize.ts` / `store.ts`）

## ① 这段代码干什么

- **`types.ts`**：全项目的**唯一契约**。题面给的 Rust 数据结构（`Point` / `Edge` / `Resource` / `LearnAction` /
  `LearnRecord` / `AnalyzeReq` / `AnalyzeResReq` / `AnalyzeProReq` 等）翻译成 TypeScript，
  外加题面那个 7 方法的 trait（`makePlan` / `analyzeRes` / `analyzePro` / `integrate` / `pointRank` / `queryPoint` / `record`）。
  还放着全部**可调默认值**（阈值、幅度、top-k…）。
- **`normalize.ts`**：把"看起来不一样其实是一个"的知识点名归到同一个 key。
- **`store.ts`**：把内存里的知识网络与学习状态**落成 JSON 文件**，并保证写得安全。

## ② 关键设计决策 + 为什么

| 决策 | 为什么这么定 |
|---|---|
| **`PointGraph` 用数组 + 下标当 pid** | 前置关系里存 `pid` 就是存下标 ⇒ **同一份真相只存一遍**，不用维护"名字↔id"两张表。合并知识点时也**不移动**其它点的 pid（只把被合并的点标 `dead`），避免全部 pid 位移引发连锁改错。 |
| **`PointNode` 加了 `name` 字段**（题面参考结构里没有） | 只有下标没有名字的话，**取不出"这个 pid 叫什么"**；而 `topoOrder` / `makePlan` / `queryPoint` 全都要用。题面明确允许自行修改设计，所以补齐并写在注释里。 |
| **不用 `enum`，用 `const` 对象 + union type** | `--experimental-strip-types` **只做类型擦除、不做语法转换**。`enum` 是**运行时语法**，擦掉就跑不了；`const` 对象 + union 类型擦掉后剩的就是普通对象，安全。 |
| **相对 import 必须带 `.ts` 后缀** | 同上：strip-types 不做扩展名解析。 |
| **归一化**：`trim → 全角转半角 → 去空白/`-`/`_`/`·` → 英文小写` | 只做**纯粹的字符串规整**，不做任何"猜同义"的动作。 |
| **🔴 `normalize()` 绝不碰括号** | `整数加减(一)` 和 `整数加减(二)` 如果自动去括号，会被**静默并成一个点**，而且不可逆。所以括号形式的等价**只允许靠 `aliases.json` 显式声明**。 |
| **合并链路 = 先查别名表 → 再归一化** | 别名表处理"人已知的同义"（如 `整数加法与减法 → 整数加减`），归一化处理"格式差异"。两者顺序不能反。 |
| **`state` 用 `Map`，但落盘走 `stateToJSON`** | 🔴 `JSON.stringify(new Map())` 得到的是 **`{}`** —— **状态会被静默丢光，而且不报错**。所以统一走 `stateToJSON` / `stateFromJSON`。 |
| **原子写**：写 `<file>.tmp` → `renameSync` 覆盖 | 演示中途 Ctrl+C 不会留下**半截 JSON**；`rename` 在同一文件系统上是原子的。 |
| **保留最近 500 条** | `answers` / `history` / `decisions` 长期跑会无限膨胀。超出按 `at` 排序裁剪（`keepRecent`），已在 README §8 写明。 |
| **`graph.json` 载入时做校验**：① `points.length === pointMention.length` ② 所有 `prevPids` / `pointPids` 下标合法 | 文件可能被手改坏。**任一不过就丢弃重建 + 告警**，绝不带着错位的 pid 继续跑（错位的 pid 会静默指向错的知识点，比崩溃更难查）。 |

## ③ 可能被追问的问题

**Q：为什么冷启动掌握度是 0.5，不是 0？**
> 因为从 0 开始，第一次答错是 `clamp01(0 − 0.25) = 0`，**状态纹丝不动**，演示时看不出任何变化。
> 从 0.5 起步，第一次答错 → 0.25，变化可见。
> 而且用 `state.has(key)` 仍然能区分"没学过"（map 里没这个 key）和"就是 0 分"（map 里有、值是 0）。

**Q：`Map` 为什么不能直接 JSON 序列化？**
> `JSON.stringify` 只序列化对象**自身的可枚举属性**，`Map` 的键值对不在属性上，所以得到 `{}`。
> 这是**静默失败**（不报错），是这类项目最经典的坑。

**Q：`dead` 点为什么删掉，而不是从数组里 splice 掉？**
> 删掉会让后面所有点的下标前移，**所有 `prevPids` 全部失效**。保留占位、标 `dead`，
> 并在 `topoOrder` / `makePlan` / `queryPoint` / 计数的地方统一跳过它，是**代价最小且不易出错**的做法。

**Q：500 条裁剪为什么按 `at` 排序而不是直接删数组头部？**
> 正常追加是升序的，但**外部可能把文件改乱**（或者手工粘贴过）。
> 显式排序之后再取最后 N 条，"最近 N 条"的语义才稳定、可复现。

**Q：`decisions.json` 是干什么的？**
> §4.13 的**决策日志**：模型每次提议学习计划，接受或拒绝我都留一条，**包含原始草稿**。
> 目的是"拒绝"这件事**可回放** —— 出了问题能查"模型当时到底提了什么、我为什么拒"。

**Q：`HistoryEntry.kind` 为什么多了个 `"Merge"`？**
> 合并知识点会**改写掌握度**（两个点的状态合成一个），它不是"学习行为"但对状态有实质影响，
> 必须留痕。早期我把它记成 `"Ask"`，会**污染"提问记录"的计数**，所以单列了一类。

⚠️ **Q：如果我说"归一化能自动合并同义知识点"——这是错的。**
> 归一化只处理**格式差异**（空格、全半角、大小写、连字符）。**真正的同义**（"整数加减法" vs "整数加减"）
> 是靠 `data/aliases.json` **显式声明**的。这是刻意的：自动猜同义会误合并，而且不可逆。
