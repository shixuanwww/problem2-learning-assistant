# 04 · 问答与检索（`qa.ts`，`QaEngine` 类）

## ① 这段代码干什么

`ask(question)`：**检索资料 → 判定"资料够不够" → 够就让模型只依据资料回答并给出来源；不够就明说"资料不足"**。
不管够不够，都会把这次提问**回填成一条学习记录**（题面：提问也是可追溯的学习行为）。

## ② 关键设计决策 + 为什么

| 决策 | 为什么这么定 |
|---|---|
| **🔴 `ask` 不在 `SimNet` 上，在独立的 `QaEngine` 上** | 问答需要一份**额外的原料：检索索引**（切好的片段 + 可选的向量）。把索引塞进 `SimNet` 会让"知识网络"同时管两件事。所以按**能力**拆接口：`SimNet` 实现题面那 7 个方法，`QaEngine` 实现 `Asker`。 |
| **检索有两条路：向量 / 关键词，按"有没有 embedding Key"自动选** | 没有向量服务时**不能让功能消失**，退化成关键词 n-gram 检索，效果差一些但结果依然可复现。 |
| **🔴 "资料不足"是**数值判定**，不是提示词** | 这是本题最关键的一处设计。如果靠"让模型自己说够不够"，那**没配 Key 时根本无法判定**，答辩一问就穿。我用的口径：<br>• 向量模式：top1 相似度 **≥ 0.45**<br>• 关键词模式：**命中片段 ≥ 1 且 词项覆盖率 ≥ 0.5**（覆盖率 = 查询去停用词后的词项，出现在命中片段里的比例）<br>两条都不满足 ⇒ `sufficient = false`、`answer = null`。 |
| **🔴 有 Key 时，模型只能把 `sufficient` 降为 false，不能升高** | 判定阈值是**下界**（"至少得有东西"）；模型看到片段后可以再判"这段跟问题无关"从而降级，但**不能凭自己的常识把"资料不足"说成"能回答"**。 |
| **🔴 模型自述"资料不足"时也降为 `answer=null`** | 光有检索阈值不够：模型完全可能一边说"资料不足，无法回答"、一边被系统当**有效回答**返回（`sufficient` 还是 true）。所以模型返回后要再检一道：命中 `isModelInsufficient()` 的正则（资料不足 / 信息不足 / 无法回答 / 文中未提及 / 不足以回答）⇒ 一律 `answer=null` + `sufficient=false`，**出处照旧返回**（便于人工复核），Ask 记录照旧回填。 |
| **不足时 `answer = null`，而不是"我猜一下"** | 题面明确要求 **不得用模型自身知识补全**。`null` 是个**可断言**的值 —— 测试里直接断言 `answer === null`。 |
| **降级路径下 `sufficient` 的语义不变** | 没 Key 就"放水"是最容易发生的堕落。所以我把判定的两条口径做成了**纯本地函数**，无 Key 时照样跑，结果一样。 |
| **🔴 `offline` 档：l1-demo 强制不联网** | 保底演示要"在任何机器上输出一致"。如果机器上恰好配了 Key，`ask` 会走模型，**输出就和没 Key 的机器不一样了**。所以 `QaEngine` 有一个 `offline: true` 选项，l1-demo 用它，**连"本机有没有 Key"都不影响输出**。 |
| **不管够不够，都 `record({kind:"Ask", ...})`** | 题面：提问也是学习行为。测试里断言"提问后 history 里 Ask 记录 +1"。 |
| **`Citation` 带 `resource` + `locator` + `snippet`** | 三段式才叫"可追溯"：哪个文件、文件里哪一节、原文哪一句。`locator` 对 md 用的是**标题路径**（如 `二年级数学 · 整数运算 / 1 整数加减法`），不是"第几段"。 |
| **`snippet` 截断到 ≤ 200 字并标省略号** | 上下文有限，也给前端展示留余地。 |

### 上下文包（L3 完成标志）

除资料片段外，还向模型**只读**注入三项（定值 N=5 / M=5，写在 README §8）：

1. 相关点的 `state`（掌握度）+ 该点相关题型的 `kindState`；
2. 相关真题（`queryPoint`）+ 该点的 `AnswerRecord`（最近 **5** 条）；
3. 相关 `HistoryEntry`（最近 **5** 条）。

**为什么强调"只读"**：这些是给模型"调整讲解详略"用的**背景**，不是资料依据。
模型要改学习状态，**只能走 `record`**（受掌握度公式约束），不能自己在回答里改。

## ③ 可能被追问的问题

**Q：`0.45` 和 `0.5` 这两个阈值怎么定的？**
> 是**先定行为、再调出来的**，不是拍脑袋：向量模式用余弦相似度，同义句一般在 0.6+、
> 沾边但不同的主题在 0.3–0.5，所以取 0.45 分界；关键词模式用"覆盖率 0.5"是因为
> 中文查询里常有语气词和冗余字，要求全部词项命中会过于苛刻，一半是比较稳的分界。
> 两个值都**集中写在 `types.ts` 里**，README §8 有账本 —— 可调、可复现。

**Q：如果问题里有资料中没有的词，覆盖率不就低了吗？**
> 这正是**想要的**。覆盖率低说明"你问的东西资料里没怎么讲"。
> 实测：问"二次根式怎么化简"（资料里完全没有），关键词模式和向量模式都判 `sufficient=false`。

**Q：`ask` 为什么不在 `SimNet` 上？题面 trait 里没有 `ask` 吗？**
> 题面的 trait 是 7 个方法（`makePlan` / `analyzeRes` / `analyzePro` / `integrate` / `pointRank` /
> `queryPoint` / `record`），**`ask` 是实现时追加的能力**（题面明确允许自行添加）。
> 我把它放在独立的 `QaEngine` 上，因为它需要检索索引这份额外原料。
> 早期版本我错把它挂在"助手接口"上又让 `SimNet` 去实现，结果 `SimNet` 缺这个方法
> （**运行时是 `undefined`，而且因为不做类型检查一直没暴露**）—— 后来按"能力"拆开接口修掉了。

**Q：无 Key 时问答降级成什么？**
> 抽取式：把**命中的原文片段**直接作为答案返回，并标出处，同时把 `fallback` 标记为
> `"extractive"`（向量降级成关键词时标 `"keyword"`）。**判定结果不变** —— 不足仍然是 `null`。

**Q：`buildContext` 是怎么找出"相关知识点"的？**
> 目前是最朴素也最可解释的做法：**问题字符串里直接出现了知识点名**。
> 粗，但**可复现、可解释**，不存在"为什么这个是相关的"这种说不清的情况。
> 我把它写成了已知的简化（README §9 有声明），升级方向是先用检索命中的片段来反查知识点。

**Q：模型回答里注明了引用编号 `[1]`，这个编号可信吗？**
> 编号是我**按检索顺序注入**的（片段 `[1]`…`[5]`），模型只是复述。
> 但要说清楚：**模型在正文里写哪个编号，我不做二次校验**（不去核验它引的那段是否真支持那句话）。
> 真正的"可追溯"是 `citations` 数组本身 —— 那是**系统生成**的，不是模型生成的。

⚠️ **Q：能说"我的问答是 RAG 吗"？**
> 可以说是检索增强（检索 → 上下文 → 生成），但**要主动说明边界**：
> 向量检索是**可选的**（没配 embedding Key 就退化成关键词），而且我**没有做语义分块和重排**，
> 切片是按标题 + 段落，粒度较粗。别把它说成"完整的 RAG 管道"。

⚠️ **Q：模型说"资料不足"这一条怎么测的？总不能每次演示都去赌模型怎么答吧？**
> 用 `QaOptions.answerOverride`（**测试注入口**）：注入一段文本就相当于"模型这样回答了"，
> 完全**不联网**。用例 32 注入"资料不足…" ⇒ 断言 `answer === null` + `sufficient === false` + Ask 记录 +1；
> 用例 33 注入正常回答 ⇒ 原样返回；注入空串 ⇒ 模拟调用失败、走抽取式降级。
> 生产路径（`server.ts` / demo）不传这个字段，所以线上行为与注入无关。
