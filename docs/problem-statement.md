## 2. 题目二本体：《AI 学习辅助网页》（PDF 第 4–11 页，逐字）

### 2.1 背景与工作流

AI 学习辅助网页
期末考试前，亚基学姐沉迷于《人狼村之谜》和追日剧，导致复（预？）习时间严重不足。
她有：
• 老师的 PPT（格式为 pptx）
• 课本 PDF
• 往年真题（格式为 pdf）
• 考试时间

问题是资料太多，她没有时间从头整理这些东西了。
于是她希望你实现一个基于 AI 的学习辅助工具，最终应形成大致如下的工作流：

代码块
```
上传资料或记录真题作答情况
   ↓
后台解析资料
   ↓
构建知识 / 题型体系
   ↓
AI 按需查询资料与学习状态
   ↓
更新学习计划
   ↓
用户学习 / 问答 / 做题
   ↓
继续上传
   ↓
更新知识体系
   ↓
调整学习计划
   ↓
AI 再次决策
```

核心：
• **原始资料(输入)**：PPT、教材，这里统一抽象成一堆在本地的 md 文件， 是所有知识和回答的事实来源。
• **知识点**：课程中需要理解和掌握的最小知识单元。
• **真题**：考察知识点的具体实例，也是判断考试重点和用户掌握情况的重要依据。
• **知识体系**：知识点之间，以及知识点、真题、原始资料之间的关系网络。
• **学习记录**：用户实际发生过的学习行为，包括提问、看过内容、做真题、答对答错、跳过等。
• **学习计划**：结合知识体系、真题分布和学习状态(可以暂不考虑)，决定接下来学什么、怎么学，具体实现可以简化为学习一串不重复的知识点，每个知识点的学习过程由多个学习动作组成
• **学习动作**：计划真正落地的一步，例如"看某段资料""解释当前知识点""做一道题""继续下一项/结束当前项"。
• **AI 学习助手**：负责理解用户表现、调用已有知识和真题、选择下一步学习动作，但不取代底层数据本身。

### 2.2 参考数据结构（coauthor by 季菓学妹）

代码块
```rust
type Resource = String; //原始资料 Path 或者 filename 之类，合理即可

//知识点
//例子 {name : "整数加减法"}
struct Point {
    name: String,
    // pid: u32, 一个单调递增的 id，表示在 graph 的 index，可选
}

//真题
// 例子 : {name:"十以内的加减"，content "2 + 3 = ?", points:[整数加减法]}
struct Problem {
    name: String,
    content: String,
    points: Vec<Point>,
}

// 单向边，from -> to, 表明学后一个知识点前要学前一个知识点
// 示例 (加减法, 乘除法)
type Edge = (Point, Point);
// 知识体系, 一个由单向边和知识点组成的图
// (_, _)的含义这个知识点是哪些其他知识点的前置知识点，以及哪些资料涉及了ta
type PointGraph = Vec<(Vec<Point>, Vec<Resource>)>;

enum ProStatus {
    Correct,
    Incorrect,
    Confuse,
}

// 用户自己上传的一次学习行为在后台的的记录
enum LearnRecord  {
    // 问了某个问题
    Ask(String),
    // 读了某个资料
    Read(Resource),
    // 做了某个习题以及做的结果
    Do(Problem, ProStatus),
    // 暂时跳过了某个知识点
    Skip(Point),
}

// 制定的计划中
enum LearnAction {
    // 读哪个资料
    Read(Resource),
    // 解释当前知识点，可能需要重复解释，根据上下文内容不同，如intro和summary
    Explain,
    // 做某一道题，这里假定为真题，如果ai自己编则需要考虑额外逻辑
    Do(Problem),
}

// 一个学习计划， 表现上为如何学习一连串知识点
// 比如 [(整数加减， [读小学课本， 解释加减法， 做加减法习题]),
// (整数乘除， [....])]
type LearnPlan = Vec<(Point, Vec<LearnAction>)>

// ai 分析一个资料产生的结果
// 示例 {resource:"小学二年级上册数学课本"， points: [乘除法...],
// edges : [(加减法, 乘除法)...]}
struct AnalyzeResReq {
    resource: Resource, //这次的分析来自哪个资料
    points: Vec<Point>, //这次分析的结果里有哪些知识点
    edges: Vec<Edge>, //这次分析的结果里的知识点之间的联系
}

// ai 分析一个问题产生的结果
// 示例 {problem : {.., content:"3 + 2 * 3"}, points:[整数加减，整数乘除] }
struct AnalyzeProReq {
    problem: Problem, //这次的分析来自哪个资料
    points: Vec<Point>, //要做出这个题目需要哪些知识点
}

enum AnalyzeReq {
    ResReq(AnalyzeResReq),
    ProReq(AnalyzeProReq),
}

// 你可以自行添加其他 helper method
trait AIAssistant {
    // 根据已有信息生成一个 plan
    fn makePlan(&self) -> LearnPlan,

    // 分析资料和问题
    fn analyzeRes(&self, resource: Resource) -> Result<AnalyzeResReq, _>,
    fn analyzePro(&self, problem: Problem) -> Result<AnalyzeProReq, _>,
    //把一次分析的结果整合进知识体系
    fn integrate(&mut self, req: AnalyzeReq),

    // 根据知识点在各个真题里的出现次数，统计数量排在前rank个的高频知识点
    fn pointRank(&self, rank: u32) -> Vec<Point>,

    // 查找一个知识点在哪些问题和资料中出现
    fn queryPoint(&self, point: Point) -> (Vec<Resource>, Vec<Problem>)

    // 记录用户的一次学习行为，并更改学习状态等
    fn record(&mut self, learn: LearnRecord),
}
```

### 2.3 Level 1：知识网络 SIMULATION

学姐上传了一整门课的 PPT、教材和历年真题，但 AI 生成的一大段总结她不想看。
她更希望系统能自动整理出：
• 一份课程知识点总结以及这些知识点之间的联系 (比如需要学完了 A, B 才能学懂 C)
• 一份历年知识点考频(统计真题里涉及到的知识点）；
• 知识点、真题和原始资料之间的关系。

同时，后续继续上传新的 PPT、教材或真题时，系统应该把新内容整合进已有知识体系
不过接入 AI 还是太过麻烦而且要花钱，于是学姐打算先模拟一个知识网络出来
也就是假定我们已经拿到了 ai 分析出来的结果 AnalyzeReq,
你需要 define 一个 SIMULATION-NETWORK type 并为ta简单实现 AIAssistant
参考type如下

代码块
```rust
struct SimulationNetWork {
    resources: Vec<Resource>,
    graph: PointGraph,
    pointMention: Vec<u32>,
}
```

要求:
• 定义一个 SimulationNetwork 类型, 并实现 integrate 方法 和 makePlan 方法
（顺带实现queryPoint, 或者在 Level2 里再实现也可以）
• makePlan方法返回的 LearnPlan 的 Vec<LearnAction> 这里可以为空, 但Vec 里的 Point 需要保持有序， 也就是如果学 B 要先学 A， 那么 B 的位置要在 A 后面, 且返回的Vec里必须每个Point都出现且仅出现一次, 简而言之，你返回的plan只需要给出一个合理的知识点学习顺序即可

### 2.4 Level 2：仿生知识网会梦到电子测试吗

在Level1中我们已经完成了一个足够使用的 模拟知识网络，现在是时候把 ai 的文件处理并入电网了
简而言之，我们现在希望为前面的知识网络实现 analyzeRes 和 analyzePro 以及 record 中的 ask branch

要求：

**1.1 从原始资料构建一套可持续更新的知识体系**

系统需要能够解析md格式文件，这些文件里有真题有资料
为了让ai的输出满足格式，你可能需要schema校验或者为ta配置tool之类的
（区分真题和资料的话可以简单点按路径或者自己定义后缀）
（如果可以的话在文件较长时进行一些合理的切分处理）
注意，处理不同资料时候会使用不同名称描述同一知识点，所以我们应该尽量把名字不同但本质相同的知识点合并；

**1.2 基于资料进行可靠问答**

用户可以针对课程内容自然语言提问。
回答必须以用户上传的资料为依据，并能够追溯到原始资料。
如果资料不足以支持答案，系统应提示说明资料不足，(ask返回的record的Ask的Option可写为None),而不是直接依赖模型自身知识补全。

完成标志
能够演示一个完整课程从"上传资料"到"可查询知识体系"的过程：
1. 上传多份课程资料和真题后，可以形成统一的知识与题型体系；
2. 查询一个知识点时，可以同时看到相关资料来源、真题和题型；
3. AI 问答能够返回资料依据，并在资料不足时拒绝无依据补全。

### 2.5 Level 3：但是我只有三天就要考试了欸

到目前为止，这个系统已经知道"这门课有什么"，但学姐真正想知道的是：我哪里不会？现在应该学什么？具体应该怎么学？
如果只是把所有知识点和考试时间一次性丢给 AI，让它生成一份知识点学习顺序，显然还不够。
你需要让 AI 真正参与学习过程，并根据用户后续的表现持续调整。

要完成

**1.1 让系统知道用户到底学得怎么样**

系统需要根据用户的学习记录维护一个抽象的学习状态，比如对各个知识点的掌握程度等
一个简单的参考是：

代码块
```rust
type State = Map<Point, f32>
```

用户的反馈这里我们抽象为主动的上传，也就是主动调用 record method
注意学习状态本身应被系统持久化，不能只存在于一次模型上下文中。

**1.2 让 AI 决定下一步学什么、怎么学**

好了，还记得吗，我们的 makePlan 返回结果依然只是告诉我们应该按什么顺序学习知识点，那个 action 依然是个空 Vec
现在让你的 AI 能结合各种上下文，填充这个Vec

完成标志
至少能够演示一段连续学习过程：
1. AI 根据已有课程数据和用户状态选择下一步学习内容与学习方式；
2. 用户上传一个record后，学习状态发生合理变化；
3. 新的作答结果能够影响之后的学习计划，例如增加薄弱题型训练、回到相关知识点或降低已掌握内容优先级；
4. AI 能够按需获取系统中的知识、真题、作答情况或学习历史完成判断；
5. 模型做出不合法操作时，后端不会直接执行。

进阶要求
• AI 主动生成问题判断用户是否真正掌握；
• 区分"概念不会""前置知识不足""会概念但不会做题"等不同情况；
• 根据多次真题作答记录区分偶然做错和稳定薄弱题型；
• 对主观题的作答过程进行分析，而不只是记录对错；
• 控制模型调用次数、Token 或整体成本；
• 保存 AI 每次决策的依据，支持回放；
• 对 AI 的下一步学习决策做自动评估；
• 针对不同任务使用不同模型或 Prompt。
• 提高语义相近但关键词不同的问题的检索效果；
• 优化大量资料下的检索、更新和存储性能。
