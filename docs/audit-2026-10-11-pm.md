## 3. 本轮修掉的 3 个问题（每条都有实测证据）

### 3.1 🔴 模型抽取没接到任何用户流程上（P0）

**修前**：全项目 `analyzeRes` / `analyzePro` **零调用者**；网页壳的上传与 `/api/analyze` 走的是
`materialReq()`（纯规则解析 `## 知识点:`）⇒ 真从课件转出来的 md（**没有声明**）上传后
**静默得到 0 个知识点**，界面还返回 `ok:true` —— 题面 L2 的"用模型解析资料构建知识体系"在网页上演不出来。

**修后**：`/api/upload`、`/api/analyze` 与启动接入都走 `net.analyzeRes/analyzePro`，逐级回落
`模型 → md 声明 → presets`，响应带 `extractedBy: "model" | "preset" | "rule"` 与 `note`；
一份都抽不出时 `console.warn` 提醒。

**实测**（起真实服务 + HTTP）：
- 无 Key 上传"无声明资料" → `extractedBy:"rule", points:0, note:"未配置 DEEPSEEK_API_KEY（该资料无 md 声明，抽出 0 点）"`（如实，不假装成功）
- 有 Key（本机可用）→ 日志 `接入资料 … ← model｜2 个知识点 / 1 条前置边`
- 上传带声明的真题 → `extractedBy:"rule", points:1`，且立刻能在 `/api/graph` 查到

### 3.2 🔴 `SimNet.analyzeRes()` 的 presets 兜底目录传错（P0，实测复现）

**修前**：`analyzeRes` 把 `dataDir` 当预设目录用，而网页壳的 `dataDir` 是 `data/.runtime`
⇒ 它去读 `data/.runtime/presets/analyze-req.json`（**永远不存在**），所谓"第三级兜底"在网页里**不可达**。

**修后**：`SimNet` 新增 `inputDir`（只读输入：`aliases.json` / `presets/`），默认等于 `dataDir`；
`analyzeRes` 改用它。**用例 24** 直接钉住：输入目录与产物目录不同时，兜底必须读输入侧，且不写产物。

### 3.3 🔴 "模型失败"被日志谎报成"模型成功"（P0，本轮**新发现**）

**怎么发现的**：修完 3.1 后，把 `DEEPSEEK_BASE_URL` 指向打不通的地址制造"必然失败"，日志却仍然写
`← model` —— 因为 `analyzeRes` 在模型失败后**内部回落到 md 声明**并返回非空 `points`，
而调用方只看"有没有 points"就标了 model。

**修后**：`analyze.ts` 新增 `ExtractSource` 与
`analyzeResourceDetailed` / `analyzeProblemDetailed`（`analyzeResource` / `analyzeProblem` 变成薄封装，
逻辑只有一份）；网页壳**只看 `by`** 决定来源，`note` 用 `shortReason()` 收敛成一行 60 字
（避免把 HTTP 响应体连 `api key` 提示一起打进日志与接口）。

**实测**（同一份 data、只有 base URL 不同）：

| 场景 | 修前日志 | 修后日志 |
|---|---|---|
| 模型不可达 | 10 行全 `← model`（**假**） | 10 行全 `← rule（TypeError: fetch failed）`（真） |
| 模型可用 | `← model` | `← model`（真） |
| Key 无效（401） | `← model`（假） | `← rule（Error: chat HTTP 401: …）`（真） |

**用例 25 / 26** 把这两条钉死：模型挂 + md 有声明 ⇒ `rule`；模型挂 + 无声明 + 有 presets ⇒ `preset`。
