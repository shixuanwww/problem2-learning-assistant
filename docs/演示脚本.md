# 题二《AI 学习辅助网页》· 演示脚本（一页纸）

> **用途**：现场演示时照着走。目标 6–8 分钟，**先跑离线保底（不依赖网络/Key），再用真模型加分**。
> **心态**：题面的评分口径是"深入提问答不出可能被认为过度使用 AI"，所以每步都**主动说出设计取舍与反例**，
> 比"功能很多但说不清"强得多。

---

## 0. 开场 30 秒（不用敲命令，先定位）

> "题二要做的是一个闭环：**资料 → 知识体系 → 学习行为 → 反馈 → 调整计划**。
> 我用 TypeScript + Node 原生能力实现，**运行时零第三方依赖**（评审机不用 `npm install` 也能跑），
> 数据落盘是 JSON + 原子写，网页壳是原生 `node:http`。
> 演示分两条：**离线保底**（确定性、不花钱、任何机器一样的结果）和**真模型**（抽取 + 问答 + 计划提议）。"

---

## 1. 主演示：离线保底（推荐先跑这条，稳）

```bash
node --experimental-strip-types demo/l1-demo.ts
```

### 照着走的 5 步（对着输出讲）

| 题面要求 | 输出里看什么 | 要主动说的一句话 |
|---|---|---|
| ① 上传资料并由后台处理 | "已接入：m01-integers.md…当前知识点：整数加减、整数乘除" | 解析出来的知识点**入图前先做归一化 + 别名合并**，所以同一份资料重复上传是幂等的 |
| ② 根据多份资料构建并持续更新知识体系 / 计划 | 知识点从 2 个长到 6 个；`pointMention=[3,2,1,1,0,1]`；计划里 6 个点按拓扑序排好 | 计划顺序 = **Kahn 拓扑分层**（前置必须先学）+ 层内按 `(是否已掌握, 掌握度, -考频, 名字)` 排序；`queryPoint` 能同时给出资料 / 真题 / 题型 |
| ③ 基于资料带出处问答（含"资料不足"） | 「整数加减法是什么」`充足=true` + 出处（文件 / 章节）；「二次根式怎么化简」`充足=false、answer=null` | **充足性是数值判定、不是让模型自觉**：向量 top1≥0.45，关键词覆盖率≥0.5；没配 Key 时还要求 top1 片段命中"话题锚点" |
| ④ 记录一份真题作答 → 更新知识点 + 题型掌握度 | 知识点 `0.50→0.25`、题型`计算` `0.50→0.25`；接着**另起一个进程**读回 `state.json` | 状态**真落盘**（这一步是起子进程读盘验证的，不是内存自说自话）；冷启动先验 0.5 是为了"第一次答错看得见变化" |
| ⑤ 多轮之后 AI 调整后续行为 | 做错后该点动作数 `3→4`（主题 + 回炉题）；连续答对跨过 0.80 后位置 `1→3`、动作收敛到 1 条；同题再错 `1.00→0.75`、Do 动作 `1→2` | 调整**只在拓扑序允许的范围内**：同层换序 / 加量 / 提前动作，**绝不把点挪到它前置点之前**；回炉题读的是 `answers.json` 的结构化记录，不解析人类可读文本 |

### 收尾再加 30 秒（这段最容易被追问，先自己说）

> "最后一屏是**模型提议被拒 → 回落规则版计划**：故意喂一条引用不存在资料 + 不存在知识点的草稿，
> 校验逐条给出拒绝理由（资料不属于该点 / 知识点不存在 / 计划遗漏 5 个点），
> 拒绝原因和**原始草稿**一起写进 `decisions.json`，可回放 —— 对应题面'模型做出不合法操作时后端不会直接执行'。"

## 2. 加分演示：真模型（30 秒决定，环境允许就跑）

```bash
cp .env.example .env        # 填 DEEPSEEK_API_KEY（可选：ZHIPU_API_KEY 走向量检索）
node --experimental-strip-types demo/full-demo.ts
```

看三处：

1. **第 1 步**：`data/materials/*.md → 模型抽取 N 个知识点`（⚠️ 模型输出**不稳定**，N 每次不同 —— 这点要主动说，见 §4）；
2. **第 3 步**：同样两个问题，一次带出处回答、一次 `资料不足`；
3. **补充演示**：**让真模型提一版计划 → 校验 → 通过则采用**（本机实测 `by=model｜accepted=true`，覆盖 22 个知识点）；
   紧接着再喂非法草稿 → 被拒 → 回落规则版。这一段是回答"**AI 到底在哪决策**"的关键证据。

> 口播要点："模型只提'知识点名 + 动作意图'，**执行权在后端**：覆盖完整、恰好一次、拓扑序、
> Read 的资料必须属于该点、Do 的真题必须真实存在，全过了才用。"

## 3. 网页壳（30 秒，只在被要求时展开）

```bash
node --experimental-strip-types src/server.ts     # http://127.0.0.1:8787
```

四个动作：

1. `/` **上传**一段 md（没有 `## 知识点:` 声明也行）→ 看响应里的 `extractedBy`（`model` / `preset` / `rule`，**如实标注**）；
2. `/ask` 问一个资料里有答案的 + 一个没有的 → 看 `sufficient` 与 `citations`；
3. `/learn` 记录一次"做错" → **刷新看计划**：该点动作数增加；
4. `/learn` 底部两个按钮：`让模型提议`（走校验）与 `喂一条非法草稿`（离线也能看拒绝 + 回落）。

> 口播要点：**网页和 CLI 调的是同一个内核**（`SimNet` / `QaEngine` / `plan.ts`），网页只是壳，没有第二套业务逻辑。

## 4. 主动暴露的 3 个取舍（评审很可能会问，先答）

1. **同义知识点合并做到哪一步**：入图前 `normalize()` + 别名表（现 16 条），入图后 `mergePoints()`；
   另外给一份**候选清单**（名字二元组 Jaccard ≥ 0.6，网页 `/api/graph` 里能看到，demo 里会打印）。
   **为什么不自动合并**：自动合并会静默吃掉一个知识点、不可逆；宁可给候选给人确认。
2. **模型抽取的粒度问题**：模型可能把"整数加减法 / 整数加法 / 整数减法"抽成 3 个点
   （我实跑 3 份短资料出过 25–29 个点）。这是**已声明的限制**；缓解手段 = 别名表 + 候选清单，
   真要做语义合并得接 embedding 且只产候选。
3. **无 Key 时怎么办**：不崩、不放水 —— 检索退化为关键词，问答退化为**抽取式**（直接返回命中原文 + 出处），
   `资料不足` 仍然是 `answer=null`；判定口径不因降级而改变。

## 5. 失败预案（现场出问题时照着说）

| 现场情况 | 这么做 | 这么说 |
|---|---|---|
| 评审机 Node < 22.6，`--experimental-strip-types` 报错 | 直接说明这是 Node 版本要求（`package.json` 的 `engines` 有写） | "运行时零依赖的代价是要求 Node ≥22.6；如果版本不够，我也可以现场用 `npm run typecheck` + 讲解代码。" |
| 没有 Key / 网络不通 | 只跑 `demo/l1-demo.ts`（它**强制离线**，连本机恰好有 Key 都不影响输出） | "保底演示是刻意做成确定性的，输出在任何机器上一致。" |
| 真模型那次输出很乱（点数暴增/边有环） | 就用这次输出讲**鲁棒性**：环检测会打破环 + 告警，保证每个点恰好进计划一次；模型失败会逐级回落 `model → md 声明 → presets`，来源如实标注 | "模型不稳定是常态，所以我把'来源'和'降级路径'都做成了可见的。" |
| 被要求"换个资料现场试" | 用网页壳 `/` 上传一段自己准备的 md | 提前在 `data/materials/` 留一份**没有声明**的 md 会更方便 |
