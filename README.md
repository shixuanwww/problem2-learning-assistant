# AI 学习辅助系统（题 2 交付说明）

> **一句话**：把散落的课程资料与历年真题，自动整理成一张**带前置关系的知识点网络**；
> 基于它生成**学习计划**、做**带出处的问答**、从**做题记录**更新掌握度、反过来调整后续计划 ——
> "资料 → 知识体系 → 学习行为 → 反馈"的闭环。
>
> 本 README 面向**快速评审**：完成度 → 怎么用 → 怎么检查 → 代码导读。
> 完整设计细节见 **`docs/README-设计详版.md`**；每个模块的《答辩问答》在 **`docs/defense/`**。

## 1. 完成度（对照题面三个 Level）

| Level | 题面要求 | 状态 |
|---|---|---|
| **L1 知识网络** | 不接 AI；integrate + makePlan（学习顺序满足前置约束、每点恰一次） | ✅ 归一化 / 别名表 / 拓扑排序 / 环检测 / 考频 / queryPoint |
| **L2 · 1.1** | 从资料构建可持续更新的知识体系（解析 / 切分 / schema 校验 / 同义点合并） | ✅ 三级抽取路径 + 手写 schema 校验 + 重试；合并 = 归一化 + 别名表 + 候选提示 |
| **L2 · 1.2** | 带出处问答；资料不足必须拒绝，不得用模型知识补全 | ✅ 向量 / 关键词双模式检索 + 数值充足性判定 + 出处追溯 |
| **L3 · 1.1** | 学习状态抽象 + **持久化**（不能只活在模型上下文里） | ✅ state/kindState，JSON 原子写，跨进程验证（`demo:persist`） |
| **L3 · 1.2** | makePlan 的 LearnAction 真填充（结合状态决定怎么学） | ✅ 动作填充 + 回炉题 + **真模型提议通道**（校验/拒绝/回落）+ 决策日志 |
| 演示 5 步 | 上传 → 建体系/计划 → 带出处问答 → 记录作答 → 调整计划 | ✅ `npm run demo` 离线走完全部 5 步 |
| 交付物 | 能操作的网页或 CLI ＋ README ＋ 演示样例数据 | ✅ **双形态**（CLI 演示脚本 + 网页壳）＋ `data/materials`、`data/problems` 样例 |
| 加分 | 网页界面 | ✅ 9 条 API + 3 个页面 + 知识点图谱（原生 SVG 分层 DAG） |

**测试**：46 条验收用例 **46 pass / 0 fail**（含 6 条网页壳端到端：子进程起真实 server 真发 HTTP）。
**已知限制**（如实声明，详见详版 §9）：语义合并默认不自动做（合并不可逆，只提示候选）；PDF/PPTX 不直接解析（先转 md）；不处理多进程并发写。

## 2. 怎么使用

**环境**：Node ≥ 22.6（`node -v` 自检）。**运行时零第三方依赖、离线可跑**（`npm install` 仅可选的 typecheck 需要）。

```bash
npm run demo          # ⭐ 保底演示：零依赖、离线、确定性输出，走完题面 5 步
npm run demo:full     # 完整演示：真调模型抽取 + 带出处问答（无 Key 自动降级，不崩）
npm run serve         # 网页壳 → http://127.0.0.1:8787（真上传 + 问答 + 计划 + 图谱）
npm run demo:persist  # 另起进程读回数据，证明持久化是真的
```

> 想接真模型：`cp .env.example .env` 填 Key。**没有 Key 也全链路可演示**（降级路径见详版 §6）。
> 所有命令请在仓库根目录执行（`data/` 按当前目录解析）。

## 3. 怎么检查（3 分钟验收清单）

```bash
# A. 全量用例（应输出 # tests 46 / # pass 46 / # fail 0）
npm test

# B. 离线演示走完题面 5 步（上传 → 体系/计划 → 带出处问答 → 作答记录 → 调整计划）
npm run demo

# C. 网页壳：起服务后浏览器开 http://127.0.0.1:8787

```

**预期看点**：
- demo 输出中问答带**出处引用**（资料路径 + 行号），资料不足时**明确拒答**而非编造；
- 作答记录后重新 makePlan：答错的知识点**回炉**（计划中出现针对它的动作）、已掌握的优先级下降；
- `demo:persist` 证明状态真落盘（新进程读回同一份 state）；
- 网页壳首页有知识点 DAG 图（悬停高亮前置链路）。

## 4. 代码导读

```
src/
  types.ts      契约：题面 trait 的 7 个方法 + 全部数据结构
  normalize.ts  名称归一化（全角/空白/连接符/大小写）+ 别名表 → 同义点合并的基础
  store.ts      JSON 持久化：原子写、500 条裁剪、载入校验
  network.ts    知识网络内核：integrate / makePlan / pointRank / queryPoint / record
                / mergePoints / 拓扑排序 / 环检测
  plan.ts       makePlan 动作填充规则 + 模型提议通道（校验→采用/拒绝→回落）
  qa.ts         问答引擎：检索（向量/关键词）→ 充足性判定 → 带出处回答
  analyze/      抽取流水线：parse（md 切分）→ llm（调用+降级）→ schema（手写校验器）
                → analyze（模型 → 声明 → presets → 如实失败 的四级兜底）
  server.ts     网页壳（原生 node:http + 手写路由，9 条 API）
demo/           l1-demo（离线5步）/ full-demo（真模型）/ verify-persist（跨进程读回）
public/         index.html（体系+图谱）/ ask.html（问答）/ learn.html（计划与记录）
data/           materials+problems（样例输入）/ aliases.json / presets/（兜底）
tests/          46 条验收用例
```

**主要设计（答辩深挖入口）**：
1. 学习顺序 = **拓扑排序**（前置边 from→to），环检测拒绝成环输入 —— L1 的核心；
2. 同义点合并 = **归一化 + 别名表 + 候选提示**，不自动合并（合并不可逆，静默吃点比报错更糟）；合并后旧名重定向，重启不丢数据；
3. 抽取走**四级兜底流水线**：模型 → 文内声明 → presets → 如实失败（每级失败都显式报告，不静默）；
4. 问答**必须可追溯**：回答带资料出处，充足性不足即拒答 —— 落实题面"不得用模型自身知识补全"；
5. 零依赖运行（`node --experimental-strip-types` 直跑 TS），无 Key 全链路可演示且**降级路径有专门用例覆盖**。
